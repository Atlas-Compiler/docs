Atlas returns errors formatted according to the **RFC 9457 Problem Details for HTTP APIs** specification (`Content-Type: application/problem+json`).

Every error response contains a stable, machine-readable `code`, human-readable `detail`, HTTP status code, a unique tracing `requestId`, and an explicit boolean `retryable` indicator so your application can make deterministic retry decisions without fragile regex string parsing.

---

## Error Response Schema

<ErrorResponseSnippet />

### Problem Details Fields

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `type` | `string` | **Yes** | An absolute URI reference that identifies the problem type. |
| `title` | `string` | **Yes** | A short, human-readable summary of the problem type. |
| `status` | `integer` | **Yes** | The HTTP status code generated by the origin server. |
| `detail` | `string` | **Yes** | A human-readable explanation specific to this occurrence of the problem. |
| `instance` | `string` | **Yes** | The request URI path where the problem occurred. |
| `requestId` | `string` | **Yes** | Unique request trace ID (e.g., `req_01j7abc123...`). Always provide this ID to Atlas support. |
| `code` | `string` | **Yes** | A snake_case machine-readable error code for client switch/case statements. |
| `retryable` | `boolean` | **Yes** | When `true`, the client may safely retry the request using exponential backoff. |
| `documentationUrl` | `string` | No | Direct link to the public documentation troubleshooting guide for this specific error code. |
| `invalidParams` | `object[]` | No | List of parameter validation errors, containing `name` and `reason` pairs. |

## Complete Error Code Reference

### 1. Authentication & Authorization Errors

| Code | HTTP Status | Retryable | Cause & Resolution |
| :--- | :--- | :--- | :--- |
| `unauthorized` | `401` | No | Missing `Authorization` header or malformed Bearer token. Check API key presence. |
| `invalid_credentials` | `401` | No | API key is revoked, expired, or invalid. Verify in the Atlas Dashboard. |
| `forbidden` | `403` | No | Caller lacks permission or token lacks the required scope (e.g. `atlas:crawl`). |
| `workspace_not_found` | `404` | No | The workspace associated with the credentials could not be located or is deleted. |
| `forbidden_origin` | `403` | No | MCP client origin header is disallowed (browser DNS rebinding defense). |
| `forbidden_host` | `403` | No | Host header mismatch during MCP connection. |

---

### 2. Validation & Request Errors

| Code | HTTP Status | Retryable | Cause & Resolution |
| :--- | :--- | :--- | :--- |
| `validation_failed` | `400` | No | Request body failed schema validation. Inspect `invalidParams` for field-level errors. |
| `bad_request` | `400` | No | Malformed JSON payload or unsupported parameters. |
| `invalid_cursor` | `400` | No | Pagination cursor has expired, is corrupted, or was generated with different parameters. |
| `invalid_workspace_slug` | `400` | No | Provided workspace slug does not conform to URL-safe naming constraints. |

---

### 3. Concurrency & Idempotency Errors

| Code | HTTP Status | Retryable | Cause & Resolution |
| :--- | :--- | :--- | :--- |
| `idempotency_conflict` | `409` | Yes | An identical request is currently executing in-flight. Wait 500ms and retry with the same key. |
| `conflict` | `409` | No | Target resource was modified or is currently in an incompatible state. |

---

### 4. Quotas & Billing Errors

| Code | HTTP Status | Retryable | Cause & Resolution |
| :--- | :--- | :--- | :--- |
| `rate_limited` | `429` | Yes | Request rate exceeded per-minute capacity. Back off according to `retryAfter`. |
| `plan_limit_exceeded` | `429` | No | Workspace reached maximum concurrent jobs allowed for its plan tier. |
| `insufficient_credits` | `402` | No | Balance is lower than required operation cost. Top up credits in the Atlas Dashboard. |
| `credits_exhausted` | `402` | No | Credit balance has reached zero. All compilation operations are halted. |

---

### 5. Upstream Target Errors

| Code | HTTP Status | Retryable | Cause & Resolution |
| :--- | :--- | :--- | :--- |
| `upstream_fetch_failed` | `502` | Yes | Target web server returned a 5xx error or dropped the connection. |
| `upstream_timeout` | `504` | Yes | Target web server failed to respond within the execution timeout (default: 30s). |
| `upstream_dns_failure` | `502` | No | Target domain does not exist or failed DNS resolution. |
| `upstream_blocked` | `502` | No | Target IP is private or restricted by SSRF protection filters. |

---

### 6. Infrastructure Errors

| Code | HTTP Status | Retryable | Cause & Resolution |
| :--- | :--- | :--- | :--- |
| `service_unavailable` | `503` | Yes | Edge cluster capacity is momentarily saturated. Safe to retry with exponential backoff. |
| `internal_error` | `500` | Yes | Unexpected unhandled exception in the edge pipeline. Contact support with `requestId`. |

## Programmatic Error Handling Recipes

Use the `retryable` field and machine-readable `code` to build resilient client applications:

<CodeGroup>
```typescript TypeScript
import { AtlasClient, AtlasError } from '@atlascompiler/sdk';

const atlas = new AtlasClient({ apiKey: process.env.ATLAS_API_KEY! });

async function compileWithRetry(url: string, maxRetries = 3) {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await atlas.compile({ url });
    } catch (err) {
      if (err instanceof AtlasError) {
        console.error(`Atlas Error [${err.code}]: ${err.message} (Request ID: ${err.requestId})`);

        if (err.code === 'validation_failed') {
          console.error('Invalid parameters:', err.invalidParams);
          throw err; // Do not retry validation failures
        }

        if (err.retryable && attempt < maxRetries) {
          const delay = Math.pow(2, attempt) * 500 + Math.random() * 200;
          console.log(`Retryable error. Retrying in ${Math.round(delay)}ms...`);
          await new Promise((resolve) => setTimeout(resolve, delay));
          continue;
        }
      }
      throw err;
    }
  }
}
```

```python Python
import time
import random
from atlascompiler import AtlasClient, AtlasError

atlas = AtlasClient()

def compile_with_retry(url: str, max_retries: int = 3):
    for attempt in range(1, max_retries + 1):
        try:
            return atlas.compile(url=url)
        except AtlasError as err:
            print(f"Atlas Error [{err.code}]: {err.message} (Request ID: {err.request_id})")

            if err.code == "validation_failed":
                raise  # Permanent failure

            if err.retryable and attempt < max_retries:
                delay = (2 ** attempt) * 0.5 + random.uniform(0, 0.2)
                print(f"Retryable error. Retrying in {delay:.2f}s...")
                time.sleep(delay)
                continue
            raise
```

```go Go
package main

import (
	"context"
	"errors"
	"fmt"
	"math"
	"math/rand"
	"time"

	"go.atlas-compiler.com/sdk"
)

func compileWithRetry(ctx context.Context, client *atlas.Client, url string, maxRetries int) (*atlas.CompileResult, error) {
	for attempt := 1; attempt <= maxRetries; attempt++ {
		result, err := client.Compile(ctx, &atlas.CompileParams{URL: url})
		if err == nil {
			return result, nil
		}

		var atlasErr *atlas.Error
		if errors.As(err, &atlasErr) {
			fmt.Printf("Atlas Error [%s]: %s (Request: %s)\n", atlasErr.Code, atlasErr.Message, atlasErr.RequestID)

			if !atlasErr.Retryable || attempt >= maxRetries {
				return nil, err
			}

			delay := time.Duration(math.Pow(2, float64(attempt))*500+float64(rand.Intn(200))) * time.Millisecond
			time.Sleep(delay)
			continue
		}

		return nil, err
	}
	return nil, errors.New("exceeded maximum retries")
}
```
